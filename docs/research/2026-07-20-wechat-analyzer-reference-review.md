# 微信聊天分析参考项目评审

## 评审范围

- [Klesenchang/wechat-analyzer](https://github.com/Klesenchang/wechat-analyzer)
- [UniUni2000/wechat-chat-analyzer](https://github.com/UniUni2000/wechat-chat-analyzer)

两者均采用 MIT License，可参考其设计思想。实现阶段优先重新设计接口与数据模型，不直接复制大段源码。

## 可复用的设计思想

### 统一导入与标准化

借鉴两个项目把原始聊天数据先归一化、再统计分析的思路。情感大师内部统一为 `Conversation`、`Participant`、`Message`、`AttachmentRef`，平台特有字段保留在只读来源元数据中。导入流程必须包含来源哈希、身份映射、去重、事务提交、幂等重导和回滚。

### 确定性统计与模型分析分层

先用可复算的统计得到消息数量、双方占比、主动发起、回复间隔、时段热力、关键词和月度趋势，再把统计摘要、证据消息与当前上下文交给模型。模型不能篡改基础统计，也不能把固定阈值直接包装成人格结论。

### 模型提供方抽象与规则兜底

参考 OpenAI-compatible provider 抽象，但密钥只能进入 Android Keystore 保护的本地配置，不能写入源码、普通 JSON 或日志。云模型不可用时，规则层仍可输出保守的沟通建议，并明确能力降级。

### 报告与诊断

参考 TXT、CSV、HTML 报告及错误诊断的思路。首期只提供本地可查看的分析结果；导出能力必须默认脱敏，并由用户主动触发。

## 不采用的做法

- 不采用数千行单文件组织；按导入、存储、统计、画像、建议、平台适配拆分。
- 不明文存储 API Key、数据库口令或聊天内容。
- 不从聊天频率直接推断性别、恋爱身份、人格类型或“好感度”。
- 不用固定阈值给人贴“讨好型”“傲娇型”等标签。
- 不把 Windows/macOS 微信数据库解密方案直接移植到 Android。
- 不自动安装依赖，不执行静默外发，不自动发送社交消息。

## 对本项目的落点

1. 历史数据基线：优先支持用户主动提供的 JSON、JSONL、CSV、TXT、HTML 和聊天截图。
2. 增量数据：无 Root 时由无障碍服务按需采集当前可见消息；必要时由 MediaProjection + OCR 补充。
3. Root 增强：独立适配器负责更深层读取，失败时回退，不影响基础应用运行。
4. 画像输出：每条结论包含证据、置信度、反证和更新时间，允许用户修正或删除。
5. 回复建议：每次输出 4—6 条不同策略、可直接复制但不会自动发送的候选回复。

## 许可与安全边界

参考项目的 MIT License 不等于聊天数据可任意处理。情感大师仅处理用户有权访问并主动授权的数据；数据默认本地加密，上传模型前最小化、脱敏，日志不记录原文。
